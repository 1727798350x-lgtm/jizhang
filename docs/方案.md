# 记账 App 方案 · v1（PWA）

> 定位：给自己用的手机记账工具，纯本地存储、离线可用、零服务器成本。
> 形态：网页应用（PWA），装到安卓桌面后以独立窗口运行，体验接近原生 App。

## 1. 目标与原则

- **目标**：打开就能记、几秒记一笔、账目一眼看清、数据只在自己手机上。
- **原则**：
  1. 本地优先：无账号、无后端、断网也能用。
  2. 快：记账路径最短化（数字键盘 + 一屏可选分类）。
  3. 数据可靠：金额用整数「分」、自动保存、可导出备份。
  4. 简单：零构建、零第三方依赖，后续想改/扩展都容易。

## 2. 范围

### v1 包含

| 模块 | 内容 |
| --- | --- |
| 记一笔 | 支出/收入、金额、分类、账户、日期、备注 |
| 明细 | 月份切换、当月收支结余、按日分组的流水、编辑/删除 |
| 多账户 | 现金/微信/支付宝/银行卡等，可增删改与排序 |
| 分类 | 内置常用分类，可自定义（名称、emoji、颜色、排序） |
| 统计 | 分类占比环形图、近 6 月趋势柱状图、收入/支出切换 |
| 外观 | 浅色 / 深色 / 跟随系统 |
| 数据 | 本地 IndexedDB、JSON 导出备份 / 导入恢复 / 清空 |

### v1 不包含（放到后续版本）

预算提醒、周期记账、CSV/Excel 导入导出、云同步、多设备、PIN 锁、多币种、账单图片、共享账本。

## 3. 信息架构

底部 4 个 Tab：**明细 / 记账 / 统计 / 设置**（「记账」为中间凸起主按钮）。

### 3.1 明细（首页）

- 顶部月份切换：`‹ 2026年10月 ›`
- 收支结余卡片：本月支出 / 收入 / 结余
- 流水列表：按天分组，组头显示当日小计；每行 = 分类 emoji + 分类名/备注 + 账户名 + 金额
- 点击一条 → 编辑 / 删除
- 空状态：引导去记第一笔

### 3.2 记一笔

- 顶部：支出 / 收入 切换
- 金额显示区（大字号，右侧显示「分」位）
- 自定义数字键盘：0–9、`.`、⌫、保存（不依赖系统键盘，防误触）
- 分类网格：一屏可选
  - 支出：餐饮、交通、购物、日用、娱乐、住房、医疗、学习、人情、其他
  - 收入：工资、奖金、理财、红包、其他
- 账户：横向 chips 选择（记住上次选择）
- 日期（默认今天，可改）、备注（可选）
- 保存 → 回明细页并 toast 提示

### 3.3 统计

- 月份切换、支出/收入切换
- 三张汇总卡：本月支出 / 收入 / 结余
- 分类占比：环形图 + 排行列表（金额、占比）
- 近 6 个月趋势：柱状图（收入 vs 支出对比）

### 3.4 设置

- 外观：浅色 / 深色 / 跟随系统
- 账户管理：新增、改名、改颜色、排序、归档
- 分类管理：支出/收入分开，新增、改名、换 emoji/颜色、排序、归档
- 数据：导出备份（JSON 文件）、导入恢复、清空数据（二次确认）
- 关于：版本号、数据说明（「数据只保存在本机浏览器，请定期备份」）

## 4. 数据设计

**金额一律用整数「分」存储**，展示时除以 100，杜绝浮点误差。

### 4.1 实体

```js
// account
{ id, name, type: 'cash'|'wechat'|'alipay'|'bank'|'other',
  initialBalanceCents, color, sortOrder, archived }

// category
{ id, kind: 'expense'|'income', name, emoji, color, sortOrder, archived }

// transaction
{ id, kind: 'expense'|'income', amountCents,
  accountId, categoryId, date: 'YYYY-MM-DD', note,
  createdAt, updatedAt }

// meta（单条）
{ key: 'settings', value: { theme, defaultAccountId, version } }
```

### 4.2 存储

- **IndexedDB**（库名 `bookkeeping`，v1），store：`accounts` / `categories` / `transactions` / `meta`
- `transactions` 建索引：`date`、`accountId`、`categoryId`
- 首次启动自动写入默认分类 +「现金」账户
- **删除语义**：已有账单引用的分类/账户只能「归档」，不硬删，避免历史账目失联
- 升级约定：schema 版本号 + 迁移函数，后续加字段不丢数据

### 4.3 计算规则

- 账户余额 = 初始余额 + Σ收入 − Σ支出
- 月度统计按 `date` 字符串（本地日历日）过滤，跨时区不漂移
- 结余 = 收入 − 支出
- 统计只从同一份 `transactions` 经纯函数计算（`stats.js`），并配单元测试，保证明细与图表数字一致

## 5. 技术方案

### 5.1 选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | 无框架，原生 ES Modules + 原生 DOM | 项目不大，零构建、加载快、维护成本低 |
| 样式 | 原生 CSS + CSS 变量 | 主题切换只需改 `data-theme` |
| 存储 | IndexedDB | 容量大、异步、浏览器持久 |
| 图表 | 手写 SVG（环形图 / 柱状图） | 不引第三方库，离线可控 |
| 图标 | 分类用 emoji，UI 用内联 SVG | 零素材成本 |
| PWA | `manifest.webmanifest` + Service Worker | 可安装、可离线 |
| 测试 | Node 内置 `node:test` | 纯函数测试，无需额外依赖 |
| 本地预览 | 自带 `dev-server.mjs` | 无依赖，手机可局域网访问 |
| 部署 | 静态托管（HTTPS） | PWA 安装/离线必须安全上下文 |

### 5.3 PWA 与离线

- manifest：`display: standalone`、`theme_color`、192/512/maskable 图标、`start_url`
- Service Worker：预缓存 app shell；静态资源 cache-first；版本号变更时清理旧缓存
- 安装条件：HTTPS + manifest + SW + 图标 → 手机 Chrome 菜单「添加到主屏幕」
- 数据在 IndexedDB，与 SW 缓存分离，更新 App 不丢数据

### 5.4 部署（三选一，需你定）

- **A. GitHub Pages**：免费稳定，需要 GitHub 账号，仓库 push 即部署
- **B. Cloudflare Pages**：免费，国内访问通常更稳，需要 Cloudflare 账号
- **C. 先局域网预览**：电脑跑 `dev-server.mjs`，手机访问 `http://192.168.x.x:端口`
  —— 能看能用，但不能「安装/离线」，适合验收功能；正式使用再上 A/B

> 后续要正式安装包（APK）时：用 Capacitor 把现有网页打包，需装 JDK + Android SDK。

## 7. 验收标准（v1 Definition of Done）

- 手机 Chrome 打开 → 添加到主屏幕 → 桌面图标启动为独立窗口
- 断网启动正常，历史数据可见
- 记一笔 ≤ 5 次点击（打开 → 数字 → 分类 → 保存）
- 关闭浏览器重开数据不丢
- 首页月度汇总 = 明细逐笔求和；分类占比合计 100%（误差 < 0.1%）
- 深色模式跟随系统 / 手动切换正常
- 导出 JSON → 清空 → 导入，数据完全一致
- 竖屏 360–430px 宽度无横向滚动；可点区域 ≥ 44px
- `stats.js` 单元测试通过

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 浏览器清缓存/换浏览器导致数据丢失 | 设置页显著「导出备份」+ 首次使用提示，v1.1 加自动提醒 |
| 非 HTTPS 无法安装/离线 | 用静态托管；局域网模式仅作预览 |
| 部分国产浏览器不弹安装入口 | 优先 Chrome / Edge，或后续 APK |
| 金额浮点误差 | 全链路整数「分」 |
| 日期时区错位 | 本地 `YYYY-MM-DD` 字符串，不用 `Date.toISOString` |
| 删分类/账户导致历史账失去归属 | 有引用时只归档不删除 |
| 自定义键盘与系统输入法冲突 | 键盘纯 HTML 按钮，不依赖系统键盘 |
